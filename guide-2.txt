M5 OBJECTIVE:

Build a secure Admin Service & Catalog CMS that allows the
G DESIGN administrator to manage:

- Service Categories
- Services
- Service Descriptions
- Service Images
- Service Status
- Display Order
- Pricing Information
- Dynamic Service Requirements

The administrator should be able to manage the service catalog
without editing source code.

PHASE 10 — SERVICE ACTIVATION RULES
============================================================

When:

is_active = false

The service must not appear publicly.

However:

Existing historical requests must remain readable.

Do not delete services that already have requests without
careful referential handling.

Prefer:

inactive

over destructive deletion.

PHASE 12 — FIELD KEY RULES
============================================================

Field keys are important because request data is stored using
them.

Examples:

business_name
preferred_color
logo_style
quantity

Rules:

- lowercase
- underscores allowed
- unique per service
- no spaces
- must be stable

Changing a field label should not destroy historical data.

Example:

Old label:

Preferred Colour

New label:

Preferred Brand Color

Historical requests should still be understandable.
